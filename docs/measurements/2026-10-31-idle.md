# Idle work after measurement, 2026-10-31

Two changes follow the [baseline](2026-10-31-session.md):

- `febbfa1c`: use direct GPU load when available, avoiding the process and DRM fdinfo walk.
  Missing direct load still uses counter deltas; switching sources resets the baseline.
- `a4e894d7`: submit nested frames only when UI recordings or visual facts change, paced
  to the host refresh deadline. Client pacing, timed commits, cursor animation and hiding,
  histogram sampling and resource expiry retain independent deadlines. Imports and client
  facts are processed without waiting for a drawing.

The same desktop, driver, fast profile and isolated GPU-backed headless sway fixture were
used: 60 Hz, 1920×1080 plus 1240×1080, 1,000 local ROMs and two built-ins, no app windows,
Xwayland or metadata requests. Each case settled for ten seconds and then ran three
30-second samples. Screenshots confirmed the Library above Dock or the live System page.
No builds or other test runs took place during sampling. The owner's session stayed running
on its previous build. These are desktop nested results; device power and DRM remain device
measurements. The baseline report describes counters and their limitations in full.

## Results

The following are elapsed-time-weighted averages across each case's 90 seconds.
CPU is percent of one core; a fully busy core is 100%.

| Measurement | Baseline Dock | Metrics-only Dock | Both Dock | Baseline System | Metrics-only System | Both System |
|---|---:|---:|---:|---:|---:|---:|
| Process CPU | 1.629% | 1.409% | 0.101% | 2.722% | 1.788% | 0.667% |
| Metrics thread CPU | 0.198% | 0.034% | 0.039% | 1.029% | 0.188% | 0.203% |
| Voluntary context switches/s | 598.3 | 582.6 | 6.4 | 588.8 | 575.1 | 22.2 |

Against baseline, the combined changes reduce CPU by 94% for Dock and 75% for System;
voluntary context switches fall by 99% and 96%. The metrics-only change reduces its own
thread's CPU by about 82%. The live System page still polls and changes its graphs every
second; Dock changes only for its clock, burn-in movement or incoming facts.

The final Dock samples ranged from 0.089–0.117% CPU and 6.27–6.47 switches/s. System ranged
from 0.349–1.058% CPU and 21.23–23.26 switches/s. These are short desktop samples, with
visible variation in CPU cost. Voluntary context switches remain a proxy: scheduler stats
were disabled and privileged tracing unavailable. No exact wakeup or battery claim follows.

| Final build observation | Dock | System |
|---|---:|---:|
| Main-loop CPU, average | 0.047% | 0.433% |
| Winit event-pump CPU, average | 0.00007% | 0.0024% |
| Per-client graphics engine busy time, range | 0.0027–0.0056% | 0.081–0.088% |
| RSS | 118.0–118.1 MiB | 132.4 MiB |
| PSS | 87.1–87.2 MiB | 101.5 MiB |
| Driver-accounted resident VRAM | 134.2–142.7 MiB | 125.8 MiB |
| Driver-accounted resident GTT | 19.2–21.8 MiB | 8.0–28.1 MiB |

The baseline client's graphics engine busy time was about 3.7%. Resident GPU buffers
include shared and reclaimable allocations; GTT can overlap process mappings. PSS depends
on sharing with other processes, including the owner's older ClamShell build. No memory
saving is inferred from these runs, and GPU accounts must not be added directly to PSS.

Warm readiness across the final build's 18 subsequent launches remained a median 87 ms
(range 80–94 ms), with both screens first composed in 85 ms (76–91 ms). These observations
are from process spawn to readiness/log receipt, not physical presentation latency.
