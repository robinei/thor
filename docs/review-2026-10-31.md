# Repository review, 2026-10-31

Reviewed baseline: `022fecba` (`settings: select the Vulkan driver at launch`). The findings below describe that baseline. Fixes are tracked in the status column and beside each
finding; each completed item includes its regression coverage.

Independent passes covered the state/library model, compositor, system/binary, UI/views, test quality,
and Android/service/security boundaries. The coordinating pass reviewed packages, boot/update scripts,
device/fan policy and the findings themselves. Some initial reviewer runs ended before their full reports;
their concrete evidence was recovered and checked, and follow-up passes filled the missing coverage.
This is a broad source review with focused reproductions, not an exhaustive audit of every line or of
the upstream kernel, Mesa, Smithay or Qualcomm firmware.

## Priorities

P1 means an exposed privilege boundary, a whole-session stall, controlling the wrong program, or a boot
failure. P2 means a bounded correctness or recovery failure. P3 means a measured maintainability or
resource-management concern. A code-confirmed blocking path is distinguished from an induced GPU or
storage stall, which was not attempted in the owner's session.

## Findings

### R01. Bind Android's ADB server to loopback

Done: the server explicitly binds `tcp:localhost:5039`. The Android launch regression executes the
script with fake services and asserts the complete server argv, without opening a listener.

`clamshell/android/clamshell-android:82–83` starts `adb -a nodaemon server`, persistently through a user
service, on port 5039. `-a` listens on all interfaces; choosing a separate port does not isolate it.
An ADB client that can reach that port can use the server's already-authorised Waydroid transport,
including Android shell commands. This is access to Android, not a demonstrated Linux root compromise.
There is no packaged host firewall restricting this listener; actual exposure depends on network
reachability. Neither security.md nor android.md records accepting this exposure.

The installed `adb --help`, the [AOSP manual](https://android.googlesource.com/platform/packages/modules/adb/%2Bshow/refs/heads/main/docs/user/adb.1.md),
the [smart-socket protocol](https://android.googlesource.com/platform/packages/modules/adb/%2B/refs/heads/android14-release/protocol.txt)
and the [server request dispatch](https://android.googlesource.com/platform/packages/modules/adb/%2B/d55d672d47b954a71bf974bda64d1b1a3d3be864/sockets.cpp)
support the distinction: smart-socket clients do not authenticate as the Android device's ADB transport
does. No network listener was started during this review.

Remove `-a` or explicitly bind `tcp:localhost:5039`. The server can still connect out to Waydroid's TCP
device. Pin the binding in a launch-argv test.

### R02. Do not wait for a render fence in the DRM event loop

Done: unexportable fences keep the same drawn buffer pending, using zero-time readiness queries
and a bounded deadline only while work is outstanding. Native fences still go to KMS. Feedback and
commit counters are captured with the drawing; cancellation, power and mode changes clear pending work.
Fence tests cover failed exports, independent outputs, readiness and cancellation without calling wait.
The DRM VM checks for scanout, screen changes, external displays and pad windows passed 27/27.

`clamshell/crates/compositor/src/presenter.rs:253–259` calls `SyncPoint::wait()` when the plane lacks
fencing or exporting the fence returns none. `drm/shows.rs:280` calls this synchronously while presenting
the frame. A slow or stuck GPU therefore holds the compositor thread, both screens and Home input.
The fallback defeats the explicit nonblocking architecture even though the normal exported-fence path
does not wait there.

Keep the frame pending while a fence becomes ready, using an event source or a worker for the wait, and
publish only after readiness. Exercise the no-export path with a deliberately unsignalled test fence
while input and the other screen keep progressing. The call path is confirmed; a real GPU hang was not
induced.

### R03. Entry keys are not unique enough to identify an entry

Done: bounded 128-bit SHA-256 keys replace the 24-bit hash. Library indexing rejects conflicting full
identities and reports them; regressions pin the concrete collision pair, control-slice isolation,
settings round trips and rejection on rebuilding the index.

`clamshell/crates/library/src/entry.rs:333–342` combines a truncated basename with only 24 bits of FNV.
These distinct IDs both produce `disc1_694d3e`:

```
games:game-427945349/disc1.cue
games:game-487404394/disc1.cue
```

A state reproduction launches both and force-kills each. Both emit
`EndRun { key: "disc1_694d3e", force: true }`. The launcher ends `LaunchUnit::slice_of(key)`
(`system/src/launch/launcher.rs:179–184`, `state/src/session/launch_unit.rs:78–79`), so both programs
belong to the same control slice. Key-based library lookups and `store.rs:388–392` settings filenames
also alias. This can control the wrong program or share persisted settings, rather than merely give
two entries the same display colour.

Give full entry identities disjoint control/storage keys. A wider digest reduces accidental collisions;
uniqueness still needs checking where the library is built. Pin the concrete pair, independent settings,
ownership and Quit/ForceKill outcomes. Do not add migrations: this repository explicitly permits changing
the format outright.

### R04. Boot publication is atomic per file, not per bootable set

Done: EFI selects a complete `thor-a` or `thor-b` slot through one loader-entry rename. The active
slot is never modified while preparing the other, and ABL still publishes its single coherent image.
Routine package fixtures inject failure before and after every publication rename, check both boot
paths, retry recovery and repeated slot alternation using the real boot-image packer.

`packages/thor-system/root/usr/bin/thor-boot:59–61` renames Image, device tree, initramfs, EFI loader and
KERNEL separately. An interruption after replacing Image but before its matching initramfs leaves EFI
booting a mixed generation, despite the earlier staging and checks. The ABL's single KERNEL artifact
remains old until its own rename; that does not make the EFI path coherent.

A scratch run of the script with OS operations stubbed and failure injected on the second publication
rename exited 73 with `Image = NEW`, `dtb = OLD`, `initramfs = OLD`, `KERNEL = OLD`. This is a publication
failure reproduction, not a physical FAT power-loss test. `tools/image/upgrade-test.sh` checks an early
mkinitcpio failure, not interruption during publication.

Publish a coherent EFI artifact, or versioned kernel/initramfs/tree files selected by one entry update.
Keep the previous bootable generation until the new one is selected. Test failure after every publication
step, asserting that either selected generation is complete.

### R05. Cap callbacks across the window's surface tree

Done: callback demand and FIFO barriers are checked throughout the window tree before taking one
pacing turn. A real-protocol regression test failed before the fix and now covers child-only, root-only,
combined and absent callbacks, preserving them until due and releasing both in one turn. The FIFO
barrier tests remain in force.

`clamshell/crates/compositor/src/pacing.rs:191–199` checks only the root for waiting frame callbacks,
though it checks all surfaces for FIFO barriers and `send_frame` sends callbacks throughout the tree.
If a game requests callbacks on its picture subsurface, while the root requests none and no FIFO barrier
is present, `waiting` is false and the cap is bypassed. A 30 fps request can therefore run at display
refresh through this path.

An isolated version of `a_pictures_subsurface_new_buffers_are_its_frame_rate` requested callbacks on its
desynchronised child, set and asserted a 30 fps policy, consumed the current pacing turn, then asked for
callbacks again at the same time. The call returned no held deadline; the assertion that the child must
wait failed. The FPS presentation change in R06 was removed for this reproduction.

Determine callback demand across the relevant window surfaces, with one pacing turn per window. Pin
child-only callbacks, root and child together, no callbacks, and FIFO-barrier interactions.

### R06. Count a shown picture without requiring its root to be shown

Done: FPS feedback follows the window's picture surface. The protocol fixture now presents the actual
child picture, with the root occluded, in direct scanout, and alongside the root. Each case asserts
exactly one frame per new picture. Root-picture coverage remains in the other presentation tests.

`clamshell/crates/compositor/src/pacing.rs:143–145` adds a window to FPS feedback only when its root was
presented. An opaque picture subsurface can occlude the root, and direct scanout can report the picture
alone. New game pictures then do not contribute to the FPS reading.

Changing only the existing subsurface FPS test's presented surface from `root()` to `picture_surface()`
fails: measured FPS is `None` instead of at least 9. The current test's synthetic render state reports
the root, so its name promises a case it does not actually cover.

Use the presented picture/surface tree to determine that the window's fresh content showed, counting
once per window. Cover an occluded root and picture-only direct scanout separately from a root picture.

### R07. Cancel a failed metadata worker reservation explicitly

Done: a failed start cancels its worker reservation without dequeuing a job. Tests cover one or all
failed starts, retry without lost or duplicate work, busy clearing, and an active worker finishing the
failed starter's share.

`clamshell/crates/system/src/library/meta/mod.rs:258` calls `waiting.next(None)` when spawning a worker
fails. `Queue::next` at 177–190 dequeues a waiting job into `fetching` when one exists; it decrements the
worker count only when nothing waits. It is not a reservation cancellation.

Reproducing that exact error-path operation for four failed reservations leaves four entries marked
fetching although no worker started. Entries can be stranded, all slots can appear busy, and the
Fetching indicator never clears.

Add a cancellation operation that releases the reserved worker without taking a job. Test one failed
spawn among working workers, all spawns failing, a subsequent retry, and the final busy indication.

### R08. Separate named-profile files from owned-profile files

Done: shared profiles use `named-` filenames, disjoint from entry/runner files. Duplicate output
filenames are rejected before any write. Keymap, curve and lights round trips cover both owner kinds
and renaming; invalid duplicate profiles leave saved data and the writer cache intact.

`clamshell/crates/system/src/store.rs:380–392` names a shared profile `<name>.json` and an owned profile
`entry-<key>.json` or `runner-<key>.json`. `Profiles::unique_name` (`state/src/profiles/mod.rs:173–180`)
checks profile names, not these generated filenames. A user can name a shared profile exactly like an
owned profile's storage stem.

`save_profiles` at store.rs:372 collects into a HashMap by filename and silently drops one colliding
profile before writing. A Store round-trip reproduction with three profiles reloads only two. The
shared persistence code covers keymaps, tone curves and lights.

Use disjoint namespaces or stable profile IDs for storage. Pin named-versus-owned, runner, rename and
save/reload cases. This collision is independent of R03: even perfectly unique entry keys do not separate
the two naming namespaces.

### R09. Forget the rule that moved a window, despite title changes

Done: live placement history keeps the exact rule that moved each window. Returning it removes that
rule despite title/app-ID changes and saves the remaining rules, preserving siblings' rules. Tests
cover manual and automatic placement, displacement and repeated returns; random sequences check that
placement history contains only distinct live windows.

`clamshell/crates/state/src/session/below.rs:93–96` records a title-specific rule when siblings share an
app ID. `window_up` at 114–122 tries to forget a rule using the window's current facts. Titles can change
while the window is below, so it no longer matches the rule that was saved.

Reproduction: open two same-app-ID windows, send one down, change its title, send it up. Placement
returns, but the original title rule remains and there is no `Save(WindowRules)` effect. A later matching
window can be sent down again against the user's explicit return action.

Retain the identity/provenance of the rule applied to that live window, or otherwise remove the intended
rule without relying on mutable presentation text. Pin the resulting rule list and save effect, not
just the window's position.

### R10. Make the one-shot Steam settings read fallible

Done: the one-shot command uses a fallible settings read, accepting absent settings but rejecting
malformed or unreadable existing files before emitting environment lines. Session startup keeps its
tolerant reader. Tests run the actual binary with missing, malformed and unreadable settings, and the
actual Steam hook with that binary to verify its notice/log branch and unchanged game launch.

`clamshell/src/commands.rs:96–104` promises an error when settings cannot be read but uses tolerant
`Store::settings()`. Store logs and skips malformed/unreadable files, returning defaults. Consequently
`clamshell/steam/steam-launch-wrapper:42–43` does not take its failure/notice branch.

The actual `clamshell --launch-env steam:42`, with isolated HOME/XDG dirs and malformed
`settings/all.json`, warns, exits zero and prints no settings. A game starts without what was requested
and without the documented notice.

Keep absent settings normal, and preserve tolerant session startup if desired, but expose malformed or
unreadable existing settings to this command as failure. Test the real command and hook failure notice
beside the existing successful environment/instance-lock test.

### R11. Keep relative pointer motion inside the scene

Done: free cursor positions are clipped to the scene on absolute and relative motion and resize.
The two outputs share a rectangular scene without gaps; crossing their seam stays continuous. Protocol
and boundary tests preserve the full relative deltas sent to clients, and the lock/confinement tests
remain unchanged.

`clamshell/crates/compositor/src/pointer.rs:227–231` integrates relative motion into the current cursor
position. `input.rs:265` applies client constraints, but `constrain_pointer` returns the requested position
unchanged when no client capture exists. There is no ordinary scene-bound clamp.

A headless test starting at (10, 10), then moving left by 10,000, produces (-9990, 10). A mouse can
therefore disappear beyond an edge and require reversing all the accumulated motion to return. This
affects libinput mice; bounded nested absolute motion can conceal it.

Clamp ordinary cursor position to the valid output region while preserving unmodified relative deltas
for clients and the existing lock/confinement rules. Test both screens, outer edges, gaps and locks.

### R12. Refresh Enter's target before dispatch

Done: Enter and pad A share target refresh and mode routing, retaining separate input sources for
press/release. Real Core/views tests cover a menu opening before another frame, ordinary activation,
and modes appearing and disappearing between Enter events.

`clamshell/crates/ui/src/core/input.rs:173–177` handles ordinary Enter without `fresh()`, unlike pad A.
Mode selection also occurs before refreshing the applicable layers.

A reproduction using the real Core and ClamShell views records Settings, opens the FPS menu, then sends
Enter before another frame. Enter activates the now-hidden FPS tile and changes its value from 0 to 30.
Pad A in the identical state leaves the value at 0 and acts through the current menu.

Refresh before choosing the mode and activation target, preserving matching press/release sources.
Add a Core test with two input events before drawing; snapshot-only interaction sequences do not cover
this stale-frame boundary.

### R13. Measure waiting glyphs consistently when fitting text

Done: fitting uses the same waiting advance as measurement and drawing. Tests check both cut
directions at two scales, with an unanswered finder and after its missing-font answer, asserting the
selected and recorded widths agree and fit the rectangle.

`clamshell/crates/ui/src/gfx/text.rs:164–166` gives a glyph awaiting font discovery zero width in
`char_width()`. Measurement and drawing reserve `waiting_advance()` at 57–63 and 194–202. Fitting thus
selects more text than drawing can keep inside the supplied rectangle.

With an unanswered font finder, fitting `ああああああABC` at 20 px into 80 px returns a drawn width of
126.24 px. The trailing Latin text can cross adjoining controls during fallback discovery.

Use the same waiting advance in fitting, measurement and recording. Test both Keep::Start and Keep::End
before and after a font result. The existing waiting-font test compares measurement and drawing, not
fitting.

### R14. Reconcile swap registration after interrupted first boot

Done: existing swap files are registered and activated on retry; fstab publication is atomic. Failed
activation leaves first boot incomplete. Package fixtures cover a previously created file, repeated
runs with active swap, failed activation and recovery, new creation and insufficient disk space.

`packages/thor-system/root/usr/lib/thor/thor-firstboot:17–33` puts fstab registration and swapon inside
the block that creates a missing swap file. An interruption after renaming `/swapfile.new` but before
adding fstab leaves a valid file that causes subsequent runs to skip both operations.

A fixture starting with that file and an empty fstab completes successfully, sets
`/var/lib/thor-firstboot`, and neither adds fstab nor calls swapon. Resume options are written anyway.
The service then stops retrying, leaving the configured hibernation setup without its disk swap.

Keep creation conditional, but reconcile registration and activation whenever the valid swap file
exists. Pin reruns after each durable step, already-active swap, and the intentional insufficient-space
case. The fixture stubs disk/system operations; it does not hibernate real hardware.

### R15. Publish the initial sensor registry as a directory

Done: the initial registry is generated and synced beside its destination, then published with one
directory rename. Fixtures pin generation/publication failures, retry, replacement of an empty
directory and preservation of learned or unknown existing data. No repair deletes a possible calibration.

`packages/thor-sensors/thor-sensors:29–45` creates the final registry directory and moves generated files
into it individually. An interrupted move can leave a nonempty directory without the marker. Every
restart then refuses to replace it, protecting possible calibration but also preventing recovery from
an interrupted first initialisation. If the marker moved before the interruption, its presence alone
can also conceal missing files.

A fixture with an early generated file and no marker exits one with the incomplete-registry warning.
Do not solve this by deleting a potentially calibrated registry. Build and validate a fresh registry
beside the final path and publish it as a whole; preserve existing learned data. Test interrupted initial
publication and an existing unit's calibrated registry separately.

### R16. Reject impossible Android Wayland frame headers

Done: impossible or unaligned sizes are rejected as malformed, separately from incomplete messages.
Reads cap pending input at the largest legal wire message. Socket-pair tests verify malformed headers
close both ends and release received descriptors, and that a maximum-sized valid message still relays.


`clamshell/crates/system/src/waydroid/wire.rs:37–38` treats a declared size below eight bytes like an
incomplete frame. `pass_on` at 102–113 keeps that invalid prefix and appends future data forever.
Malformed data therefore does not end the connection as security.md says.

A socket-pair reproduction using the unchanged module consumes 262,144 zero bytes, drains zero bytes
from the parser and keeps the relay alive. Continued traffic grows the separate filter's memory. This
was not a session OOM test or proof that an ordinary Android app can directly submit arbitrary host
Wayland messages.

Distinguish invalid from incomplete input, reject impossible sizes/alignment and bound pending data.
Test closure and cleanup of both relay ends on malformed traffic, including partial valid messages.

### R17. Cursor preloading only partly removes drawing-path file I/O

Done: all 36 supported shapes are loaded before entering either backend. The drawing cursor owns
only prepared image data and textures, with no theme/file loader; missing images use the built-in
fallback. Only the nearest requested size is retained. Tests cover uncommon shapes and fallback without
late loading, and the existing nested cursor/damage checks exercise rendering.

`clamshell/crates/compositor/src/cursor.rs:112–129` preloads 17 cursor shapes. `loaded` at 332–338 reads
any other requested shape through `images`, which calls theme lookup and `std::fs::read` at 147–152.
This runs while generating cursor render elements. A valid uncommon shape can therefore put home/theme
storage latency back on the compositor thread.

Load all advertised named shapes before entering the loop, or resolve them on a worker and show a
cached fallback meanwhile. Test a non-preloaded shape with the loader held pending. The blocking call
path is confirmed; no stalled mount was introduced into the owner's session.

### R18. Move startup file work outside compositor startup

Done: presets are written before entering either backend. Wiring receives the same saved stick and
player snapshot used to initialise state and no longer rereads those files in the startup callback.
The workspace and nested startup checks cover both wiring and launch behaviour.

`clamshell/src/session.rs:122–140` runs the start callback on the compositor thread. In that callback,
`system/src/wiring/mod.rs:149–156` writes FEX presets and rereads persisted sticks/controllers already
loaded into state. `launch/fex.rs:23–26` reaches the atomic writer, including file and directory
`sync_all()` calls in `os/fs.rs:19–23`.

This is mostly startup latency rather than recurring frame work, but stuck home storage can still
hold compositor startup and violates the stated boundary. Pass the already-read input configuration
to wiring and initialise presets before the loop or on a worker with launch ordering. The call path
is confirmed; no real storage stall was induced.

### R19. Bound subprocesses inside nested-test waits

Done: screenshot and control probes use the active wait's remaining deadline, or ten seconds outside
a wait. Nested waits inherit the earlier deadline, and late predicate success is rejected. Fixtures
stall each probe, verify the subprocess is reaped and preserve the active description. The fixtures
run in tools/check.sh; CI also has a 15-minute job limit.

`clamshell/tests/nested_env.py:113–121` calls its predicate synchronously. The image probe at 135,
screenshot at 143 and control command at 146 use subprocess.run without deadlines. A blocked child can
therefore prevent the surrounding ten-second wait from ever checking its clock or reaching teardown.
This harness runs in `tools/check.sh` and the pre-commit hook.

A fake grim that sleeps 350 ms and returns a valid image makes a nominal 50 ms wait return success
after 360 ms. An indefinitely blocked probe would never return. Add child deadlines, propagate timeout
errors with the active wait description, and recheck the deadline before accepting success. Pin a
deliberately stalled probe. A short explicit CI job timeout is a backstop, not a substitute for harness cleanup.

### R20. Bound cache retention across historical UI sizes

`clamshell/crates/ui/src/gfx/canvas.rs:32–34,63–72` keys glyphs by exact floating-point pixel-size bits
without eviction. Text size follows screen height (`toolkit/style.rs:80–87`), so desktop resizing adds
more sizes. Icon masks likewise retain their historical sizes.

A synthetic workload measuring 62 ordinary characters at 600 sizes raises RSS from 13,756 to 46,592 kB;
repeating those sizes reuses the retained entries. This measures cache retention, not a live-session
leak rate. The device's fixed panel sizes are less exposed than the nested desktop path.

Bound inactive sizes or adopt a deliberate quantisation policy, keeping the current steady-frame
allocation guarantees. Add a resize-workload bound rather than a timing-sensitive RSS assertion.

## Architecture and maintainability

The state/effect/thread split and the separation of UI framework from views are useful and mostly
clear. These findings do not justify replacing that architecture. State outcomes, settle ordering,
retained damage and allocation tests provide substantial protection; another 256,000 random events
passed during the review while focused counterexamples still found gaps.

The recurring problems are narrower:

- **Identity is being asked to do too much.** Mutable titles select persistent rules; short display-like
  keys identify process groups and files; human profile names share a namespace with generated names.
  Separate presentation labels from identity and check uniqueness at the boundary that accepts data.
- **Failure paths need their own operations.** Taking the next queue job is not cancelling a reservation;
  tolerant startup loading is not a successful one-shot settings request; existence is not completion
  of a multi-step setup. Name and test those distinct outcomes explicitly.
- **The nonblocking boundary is a rule without a complete check.** The new launch path correctly keeps
  package reads on workers, but GPU fallback waits, cursor cache misses and startup callbacks remain
  exceptions. Audit complete call paths, including the uncommon branch, rather than common-path timing.
- **Surface-tree behaviour is tested through root-only fixtures.** FPS and cap policy need examples with
  the root occluded or idle. Extend existing real/headless client tests rather than building another
  presentation model for tests alone.
- **Package recovery is outside the routine test boundary.** Rust tests and the nested compositor do not
  exercise firstboot, boot publication or sensor-registry transactions. Add cheap temporary-filesystem
  fixtures and syntax checks to the routine check script; a kernel cross-build or whole VM run on every
  commit is unnecessary.

The broad wording about allocations in AGENTS.md should be read alongside architecture.md and
apply_alloc.rs, which explicitly cover warmed, steady-state events. This review does not classify
allocations while building a persisted rule/save as a new correctness defect. Likewise, a documented
unimplemented feature is not a newly discovered bug.

## Suggested order of work

1. Close the ADB listener exposure (R01).
2. Make entry/storage identities disjoint (R03, R08), pinning control isolation and round trips.
3. Make boot/setup publications recoverable (R04, R14, R15), with package fixtures first so failures
   can be injected at every publication boundary before touching an image or publishing device updates.
4. Remove the GPU wait from the event loop (R02), then the cursor/startup I/O exceptions (R17, R18).
5. Fix surface-tree cap and FPS behaviour (R05, R06) and the stale input target/scene edge cases
   (R11, R12), adding cases to the existing compositor/Core tests.
6. Repair metadata failure recovery, rule forgetting, strict hook errors and font fitting
   (R07, R09, R10, R13); each is a bounded change with its own regression.
7. Bound the Android relay and test probes (R16, R19), then address measured cache retention (R20).

Keep these as separate concerns in commits, with the regression for each failure in the same change.

## Verification and limits

- The review's production baseline had just passed tools/check.sh, the full VM suite (156/156 before
  the Vulkan setting), and the subsequent launch-and-quit VM check (3/3). Those passes do not disprove
  the narrower counterexamples above.
- During this review, 32 seeds × 8,000 random state events passed (256,000 events). Syntax checks passed
  for 49 tracked shell/package files and 12 Python files in the coordinating pass. Another reviewer
  checked the narrower packages/tools/tests/Android/Steam subset independently.
- State and command reproductions used isolated data or existing test interfaces. Compositor variants
  and Store tests were built in scratch copies; expected failures were retained as evidence, not added
  as failing tests to the repository. Package fixtures redirected paths and stubbed system operations.
- No full VM suite was repeated for this read-only review. No owner-session interaction, listener,
  physical power interruption, real GPU hang, device hibernation or firmware exercise was introduced.
- The review does not close documented device checks: A740 stability, the private Turnip ICD path
  through Proton ARM64, physical colour/scanout behaviour and handheld input/suspend behaviour remain
  device work. The documented randomised-client and other protocol GAPs remain gaps, not proof of bugs.

Scratch evidence was kept under `/tmp/thor-review-20261031/`, `/tmp/thor-review-compositor-fps/`,
`/tmp/thor-system-review.ldLkq0/` and the corresponding `/tmp/thor-*-review*.log` files. Those temporary
paths are supporting session artifacts; the triggers and required regression outcomes above are the
durable record.
